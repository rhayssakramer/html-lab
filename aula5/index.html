01 · O QUE SÃO FORMULÁRIOS

A ponte entre o usuário e o servidor

Formulários são a principal forma de um usuário enviar dados para um site. Toda vez que você faz login, pesquisa no Google, compra algo ou comenta em um post, está usando um formulário HTML.

Onde os formulários aparecem?

  • Autenticação: login, cadastro, recuperação de senha
  • Busca: barras de pesquisa e filtros
  • Comércio: carrinho, checkout e pagamento
  • Contato: fale conosco, feedback, suporte
  • Configurações: perfil, preferências, upload de avatar

Como funciona o fluxo?

1. Usuário preenche

Os campos (input, select, textarea) recebem os dados digitados.

2. Navegador valida

Antes de enviar, o navegador checa regras como required, type="email" e pattern.

3. Dados são enviados

O navegador monta pares nome=valor e faz uma requisição HTTP para a URL do action.

4. Servidor responde

O back-end processa, valida de novo, salva e devolve uma nova página ou um redirecionamento.

💡 Dica: Lembra da Aula 1 (Client x Server)? Formulários são exatamente a parte Request dessa conversa!
02 · A TAG <form>

O container de todos os campos

A tag <form> agrupa os campos e define para onde e como os dados serão enviados.

<form action="/cadastro" method="post">
    <label for="nome">Nome</label>
    <input type="text" id="nome" name="nome">

    <button type="submit">Enviar</button>
</form>

Todos os atributos do <form>

AtributoPara que serveValores
actionURL que recebe os dadosURL (padrão: a própria página)
methodMétodo HTTP de envioget (padrão), post, dialog
enctypeFormato dos dados no POSTapplication/x-www-form-urlencoded, multipart/form-data, text/plain
targetOnde abrir a resposta_self, _blank, _parent, _top, nome de iframe
autocompleteLiga/desliga o preenchimento automáticoon, off
novalidateDesativa a validação nativabooleano
nameNome do formulário (acessível via document.forms)texto
accept-charsetCodificação de caracteresUTF-8
relRelação com o destinonoopener, noreferrer, external
⚠️ Importante: Não é permitido colocar um <form> dentro de outro <form>. Se precisar de campos "fora" do form, use o atributo form (veja a seção de Hacks!).
03 · GET, POST E ENCTYPE

Como os dados viajam

O atributo method decide se os dados vão na URL (GET) ou no corpo da requisição (POST).

📬 GET

<form action="/buscar" method="get">
    <input name="q" value="html">
</form>

<!-- Resultado: -->
/buscar?q=html
  • Dados ficam visíveis na URL
  • Pode ser salvo nos favoritos e compartilhado
  • Ideal para buscas e filtros

📦 POST

<form action="/login" method="post">
    <input name="user" value="ana">
</form>

<!-- Corpo da requisição: -->
user=ana
  • Dados vão no corpo (não aparecem na URL)
  • Sem limite prático de tamanho
  • Ideal para login, cadastro e uploads

Os 3 tipos de enctype

enctypeComo os dados ficamQuando usar
application/x-www-form-urlencodednome=Ana+Silva&idade=25Padrão. Formulários comuns
multipart/form-dataDados divididos em "partes" com boundaryObrigatório para upload de arquivos
text/plainnome=Ana SilvaApenas para debug (evite)
 
<!-- Upload de arquivo SEMPRE precisa disso: -->
<form action="/upload" method="post" enctype="multipart/form-data">
    <input type="file" name="avatar">
    <button>Enviar foto</button>
</form>
⚠️ Cuidado: Nunca use GET para senhas ou dados pessoais — eles ficam no histórico do navegador, nos logs do servidor e podem vazar pelo cabeçalho Referer.
✨ Curiosidade: HTML puro só suporta get, post e dialog. Métodos como PUT e DELETE só são possíveis via JavaScript (fetch).
04 · NAME E VALUE

Sem name, sem dados

O atributo name é a chave e o value é o valor que chegam ao servidor. Um campo sem name simplesmente não é enviado.

<input type="text" name="cidade" value="Recife">   <!-- enviado: cidade=Recife -->
<input type="text" value="Olinda">                 <!-- NÃO é enviado (sem name) -->

Regras que pegam muita gente

SituaçãoÉ enviado?
Campo sem name❌ Não
Campo com disabled❌ Não
Campo com readonly✅ Sim
Checkbox/radio não marcado❌ Não
Checkbox marcado sem value✅ Sim, com valor on
type="hidden"✅ Sim
Botão de submit clicado (com name)✅ Sim, apenas o botão clicado

Vários valores com o mesmo name

<input type="checkbox" name="hobby" value="ler" checked>
<input type="checkbox" name="hobby" value="correr" checked>

<!-- Enviado: hobby=ler&hobby=correr -->
<!-- Em PHP use name="hobby[]" para receber como array -->
💡 Dica: id serve para o HTML/CSS/JS e para o <label>. name serve para o envio. Normalmente os dois existem e podem ter o mesmo valor.
05 · INPUTS DE TEXTO

Um type para cada tipo de dado

A tag <input> é void (não tem fechamento) e muda completamente de comportamento conforme o atributo type. Escolher o tipo certo dá validação grátis e abre o teclado certo no celular.

typeUsoBônus do navegador
textTexto livre (padrão)—
passwordSenhasOculta caracteres, gerenciador de senhas
emailE-mailValida formato, teclado com @
telTelefoneTeclado numérico (não valida formato)
urlEndereços webValida https://..., teclado com .com
searchBuscaBotão "x" para limpar, tecla "Buscar"
numberQuantidadesSetas +/-, valida min/max/step
 
<input type="text"     name="nome"     placeholder="Seu nome">
<input type="password" name="senha"    minlength="8">
<input type="email"    name="email"    placeholder="voce@email.com">
<input type="tel"      name="telefone" placeholder="(81) 99999-9999">
<input type="url"      name="site"     placeholder="https://">
<input type="search"   name="q"        placeholder="Buscar...">
<input type="number"   name="qtd"      min="1" max="10" step="1">

👀 Resultado Visual:

⚠️ Pegadinha: Não use type="number" para CPF, CEP, cartão ou telefone! Ele remove zeros à esquerda, aceita e (notação científica) e muda o valor com a rodinha do mouse. Use type="text" + inputmode="numeric".
06 · DATAS E HORAS

Calendários nativos, sem biblioteca

Os tipos de data abrem um seletor nativo do sistema. O valor enviado é sempre no formato ISO, independente de como aparece na tela.

typeValor enviado
date2026-11-28
time14:30
datetime-local2026-11-28T14:30
month2026-11
week2026-W48
 
<!-- Só permite datas a partir de hoje até o fim de 2027 -->
<input type="date" name="reserva" min="2026-11-28" max="2027-12-31">

<!-- Horário comercial, de 30 em 30 minutos (step em segundos) -->
<input type="time" name="hora" min="08:00" max="18:00" step="1800">

👀 Resultado Visual:

✨ Hack: Em JavaScript, input.valueAsDate retorna um objeto Date e input.valueAsNumber retorna o timestamp — sem precisar fazer parse de string!
07 · INPUTS ESPECIAIS

Cores, sliders, arquivos e campos invisíveis

type="color"

Abre o seletor de cores. Valor sempre em hexadecimal minúsculo (#ff6b35).

<input type="color" name="cor" value="#ff6b35">

type="range"

Slider numérico. Padrão: min=0, max=100, step=1.

<input type="range" name="volume" min="0" max="10" value="5">

type="file"

Upload de arquivos. Exige method="post" e enctype="multipart/form-data".

<input type="file" name="docs" accept=".pdf,image/*" multiple>

type="hidden"

Envia dados que o usuário não vê (ID do produto, token CSRF). Não é segredo: aparece no código-fonte!

<input type="hidden" name="produto_id" value="42">

type="image"

Botão de envio em forma de imagem. Envia também as coordenadas do clique (x e y).

<input type="image" src="enviar.png" alt="Enviar">

Atributos exclusivos do type="file"

AtributoExemploEfeito
acceptimage/*, .pdf,.docx, video/mp4Filtra os tipos no seletor
multiple—Permite selecionar vários arquivos
captureuser (frontal), environment (traseira)Abre a câmera direto no celular
webkitdirectory—Permite selecionar uma pasta inteira

👀 Resultado Visual:

⚠️ Segurança: accept é só uma sugestão para o seletor. O usuário pode escolher "Todos os arquivos". Sempre valide o tipo real e o tamanho no servidor.
08 · CHECKBOX E RADIO

Várias escolhas ou apenas uma

☑️ Checkbox — várias opções

<label>
  <input type="checkbox"
         name="skill" value="html"
         checked>
  HTML
</label>
<label>
  <input type="checkbox"
         name="skill" value="css">
  CSS
</label>

🔘 Radio — só uma opção

<label>
  <input type="radio"
         name="plano" value="free"
         checked>
  Grátis
</label>
<label>
  <input type="radio"
         name="plano" value="pro">
  Pro
</label>

O que agrupa os radios é o mesmo name. Radios com nomes diferentes não se "desmarcam" entre si.

👀 Resultado Visual:

Quais você conhece?
Escolha um plano
✨ Hack — checkbox indeterminado: o terceiro estado (traço "—") só existe via JavaScript: checkbox.indeterminate = true. Perfeito para um "selecionar todos" quando só alguns itens estão marcados.
💡 Dica: Para um único checkbox obrigatório (ex.: "Aceito os termos"), use required. Para radios, basta colocar required em um deles do grupo.
09 · BOTÕES

Enviar, limpar ou só clicar

Prefira <button> a <input type="submit">: ele aceita HTML dentro (ícones, <strong>, etc.).

typeComportamento
submitEnvia o formulário (é o padrão!)
resetVolta todos os campos para o valor inicial
buttonNão faz nada sozinho — use com JavaScript
⚠️ Bug clássico: um <button> sem type dentro de um form é submit. Aquele botão "Mostrar senha" vai enviar o formulário! Sempre declare type="button" em botões que não enviam.

Um formulário, vários destinos

Os atributos form* no botão sobrescrevem os do <form> só para aquele clique:

<form action="/artigo/salvar" method="post">
    <textarea name="conteudo"></textarea>

    <button type="submit">Publicar</button>
    <button type="submit" formaction="/artigo/rascunho" formnovalidate>
        Salvar rascunho
    </button>
    <button type="submit" formaction="/artigo/preview" formtarget="_blank">
        Pré-visualizar
    </button>
</form>
Atributo no botãoSobrescreve
formactionaction
formmethodmethod
formenctypeenctype
formtargettarget
formnovalidatenovalidate
✨ Hack: Pressionar Enter em um campo de texto aciona o primeiro botão de submit do form. Coloque a ação principal primeiro no HTML (dá para reordenar visualmente com CSS).
10 · TEXTAREA

Textos longos com várias linhas

Diferente do <input>, o <textarea> tem tag de fechamento e o valor inicial fica entre as tags (não existe atributo value).

<label for="bio">Sobre você</label>
<textarea id="bio" name="bio" rows="4" cols="40"
          maxlength="280" placeholder="Conte um pouco..."></textarea>
AtributoEfeito
rows / colsAltura (linhas) e largura (caracteres) visíveis
minlength / maxlengthLimites de caracteres
wrapsoft (padrão) ou hard (envia as quebras visuais; exige cols)
spellcheckLiga/desliga o corretor ortográfico
dirnameEnvia também a direção do texto (ltr/rtl)
⚠️ Pegadinha: qualquer espaço ou quebra de linha entre <textarea> e </textarea> vira conteúdo! Escreva as tags coladas quando quiser o campo vazio — senão o placeholder nem aparece.

Controlando o redimensionamento com CSS

textarea {
    resize: vertical;      /* none | both | horizontal | vertical */
    field-sizing: content; /* 🆕 cresce sozinho conforme o texto! */
    min-height: 4lh;       /* 4 alturas de linha */
}

👀 Resultado Visual:

✨ Hack: field-sizing: content faz o textarea (e até inputs e selects) crescerem automaticamente com o conteúdo, sem uma linha de JavaScript. Funciona nos navegadores baseados em Chromium; nos outros, o campo apenas mantém o tamanho fixo.
11 · SELECT, OPTION, OPTGROUP E DATALIST

Listas de opções

Select básico

<label for="estado">Estado</label>
<select id="estado" name="estado" required>
    <option value="" disabled selected>Selecione...</option>
    <option value="PE">Pernambuco</option>
    <option value="SP">São Paulo</option>
    <option value="RJ">Rio de Janeiro</option>
</select>

Truque do placeholder: a primeira option com value="" faz o required funcionar — o usuário é obrigado a escolher outra.

Agrupando com optgroup

<select name="linguagem">
    <optgroup label="Front-end">
        <option>HTML</option>
        <option>CSS</option>
    </optgroup>
    <optgroup label="Back-end" disabled>
        <option>Python</option>
    </optgroup>
</select>

Seleção múltipla

<!-- Ctrl/Cmd + clique para escolher vários. size = linhas visíveis -->
<select name="frutas" multiple size="4"> ... </select>

Datalist: autocomplete com texto livre

O <datalist> sugere opções, mas o usuário pode digitar qualquer coisa. É um "meio-termo" entre input e select.

<input list="navegadores" name="navegador">
<datalist id="navegadores">
    <option value="Chrome">
    <option value="Firefox">
    <option value="Safari">
    <option value="Edge">
</datalist>

👀 Resultado Visual:

✨ Hack: <datalist> funciona também com type="range" (mostra marcações no slider), type="color" (paleta sugerida) e type="date".
12 · LABEL, FIELDSET E LEGEND

Dando nome e estrutura aos campos

Todo campo precisa de um <label>. Ele é lido pelos leitores de tela e aumenta a área de clique: clicar no texto foca o campo (ou marca o checkbox).

Forma 1: explícita (for + id)

<label for="email">E-mail</label>
<input type="email" id="email"
       name="email">

Mais flexível para layout. O for deve ser igual ao id.

Forma 2: implícita (aninhada)

<label>
    <input type="checkbox" name="news">
    Quero receber novidades
</label>

Ótima para checkbox e radio. Não precisa de id.

Fieldset e Legend: agrupando campos relacionados

<fieldset>
    <legend>Endereço de entrega</legend>
    <label for="cep">CEP</label>
    <input id="cep" name="cep" inputmode="numeric" autocomplete="postal-code">
    <label for="rua">Rua</label>
    <input id="rua" name="rua" autocomplete="address-line1">
</fieldset>

O leitor de tela anuncia a legend ao entrar no grupo: "Endereço de entrega, grupo. CEP, editar texto". Para grupos de radio, fieldset + legend é essencial: é a "pergunta" das opções.

✨ Hack: <fieldset disabled> desabilita todos os campos dentro dele de uma vez. Ótimo para travar o formulário enquanto envia!
⚠️ Nunca: use o placeholder como substituto do label. Ele some ao digitar, tem contraste baixo e muitos leitores de tela o ignoram.

14 · AUTOCOMPLETE

Deixe o navegador preencher por você

O atributo autocomplete aceita tokens padronizados que dizem ao navegador e aos gerenciadores de senha exatamente o que cada campo é. Formulários de checkout ficam com um clique!

CategoriaTokens
Nomename, given-name, family-name, nickname
Contatoemail, tel, tel-national
Loginusername, current-password, new-password, one-time-code
Endereçostreet-address, address-line1, address-level2 (cidade), address-level1 (estado), postal-code, country
Cartãocc-name, cc-number, cc-exp, cc-csc
Outrosbday, organization, url, sex, language
 
<!-- Login -->
<input type="email"    name="email" autocomplete="username">
<input type="password" name="senha" autocomplete="current-password">

<!-- Cadastro: o gerenciador sugere uma senha forte -->
<input type="password" name="nova" autocomplete="new-password">

<!-- Código SMS: o celular sugere o código recebido -->
<input type="text" name="otp" inputmode="numeric" autocomplete="one-time-code">

<!-- Seções diferentes no mesmo form -->
<input name="cep_entrega"  autocomplete="shipping postal-code">
<input name="cep_cobranca" autocomplete="billing postal-code">
⚠️ Mito: autocomplete="off" em campos de senha é ignorado pela maioria dos navegadores (de propósito: gerenciadores de senha aumentam a segurança). Use new-password se não quiser o preenchimento da senha salva.
15 · VALIDAÇÃO NATIVA

Validação sem JavaScript

O navegador bloqueia o envio e mostra uma mensagem quando alguma regra é violada. Tudo só com atributos!

<!-- Obrigatório -->
<input name="nome" required>

<!-- Formato de e-mail -->
<input type="email" name="email" required>

<!-- Entre 3 e 20 caracteres -->
<input name="usuario" minlength="3" maxlength="20">

<!-- Idade de 18 a 120 -->
<input type="number" name="idade" min="18" max="120">

<!-- Preço com centavos (sem step, só aceita inteiros!) -->
<input type="number" name="preco" min="0" step="0.01">

<!-- CEP: 5 dígitos, hífen opcional, 3 dígitos -->
<input name="cep" pattern="\d{5}-?\d{3}" title="Formato: 00000-000">

Regras do pattern

  • É uma expressão regular do JavaScript
  • Já é ancorada: pattern="\d{3}" equivale a ^\d{3}$
  • Campo vazio passa no pattern — combine com required
  • O title aparece junto da mensagem de erro (dica do formato)

Padrões úteis

Dadopattern
CEP\d{5}-?\d{3}
CPF\d{3}\.?\d{3}\.?\d{3}-?\d{2}
Celular BR\(?\d{2}\)?\s?9\d{4}-?\d{4}
Placa Mercosul[A-Za-z]{3}\d[A-Za-z]\d{2}
Senha forte(?=.*\d)(?=.*[a-z])(?=.*[A-Z]).{8,}
Apenas letras[A-Za-zÀ-ÿ\s]+

👀 Resultado Visual: tente enviar vazio ou com dados errados

⚠️ Regra de ouro: validação no navegador é para UX, não segurança. Qualquer pessoa pode remover o required no DevTools ou enviar dados direto para a API. Sempre valide no servidor.
16 · PSEUDO-CLASSES CSS PARA FORMULÁRIOS

Estilizando cada estado

O CSS sabe o estado de cada campo. Dá para criar feedback visual completo sem JavaScript.

Pseudo-classeSeleciona campos...
:focus / :focus-visibleEm foco / em foco via teclado
:focus-withinElemento pai que contém um campo em foco
:valid / :invalidQue passam / não passam na validação
:user-valid / :user-invalid🆕 Válidos/inválidos só depois que o usuário interagiu
:required / :optionalCom / sem required
:in-range / :out-of-rangeDentro / fora de min e max
:placeholder-shownQue estão mostrando o placeholder (vazios)
:checkedCheckbox, radio ou option selecionados
:indeterminateCheckbox indeterminado ou radio de grupo sem seleção
:disabled / :enabledDesabilitados / habilitados
:read-only / :read-writeSomente leitura / editáveis
:defaultBotão submit padrão ou opção marcada inicialmente
:autofillPreenchidos automaticamente pelo navegador
 
/* Só fica vermelho DEPOIS que o usuário mexeu (não ao abrir a página) */
input:user-invalid { border-color: crimson; }
input:user-valid   { border-color: seagreen; }

/* Asterisco automático nos labels de campos obrigatórios */
label:has(+ input:required)::after { content: " *"; color: crimson; }

/* Destaca o grupo inteiro quando algum campo está em foco */
fieldset:focus-within { border-color: #ff6b35; }

/* Pinta checkbox, radio, range e progress com a cor da marca */
form { accent-color: #ff6b35; }

/* Desabilita o botão enquanto o form for inválido */
form:invalid button[type="submit"] { opacity: .5; pointer-events: none; }

Floating label só com CSS

<div class="campo">
    <input id="f-email" placeholder=" ">
    <label for="f-email">E-mail</label>
</div>

.campo { position: relative; }
.campo label { position: absolute; left: 12px; top: 12px; transition: .2s; }
.campo input:not(:placeholder-shown) + label,
.campo input:focus + label { top: -10px; font-size: .75rem; }

17 · CONSTRAINT VALIDATION API

Controle total da validação com JS

Todo campo de formulário tem uma API de validação embutida. Você aproveita as regras do HTML e personaliza mensagens e comportamentos.

Método / propriedadeO que faz
el.checkValidity()Retorna true/false e dispara o evento invalid
el.reportValidity()Igual ao anterior, mas mostra o balão de erro
el.setCustomValidity(msg)Define um erro personalizado ("" limpa o erro)
el.validationMessageMensagem de erro atual, no idioma do navegador
el.willValidateSe o campo participa da validação
el.validityObjeto ValidityState com o motivo do erro

Propriedades do ValidityState

valueMissing

Campo required vazio

typeMismatch

Não é e-mail/URL válido

patternMismatch

Não bate com o pattern

tooShort / tooLong

Fora de minlength/maxlength

rangeUnderflow / rangeOverflow

Abaixo do min / acima do max

stepMismatch

Não respeita o step

badInput

O navegador não conseguiu converter (ex.: letras em number)

customError

Erro definido via setCustomValidity

valid

true se nenhum erro acima

Exemplo: confirmar senha + mensagens em português

const senha = document.querySelector('#senha');
const confirma = document.querySelector('#confirma');

confirma.addEventListener('input', () => {
    confirma.setCustomValidity(
        confirma.value !== senha.value ? 'As senhas não conferem' : ''
    );
});

// Mensagem personalizada para cada tipo de erro
const email = document.querySelector('#email');
email.addEventListener('invalid', () => {
    if (email.validity.valueMissing) email.setCustomValidity('Informe seu e-mail 🙂');
    else if (email.validity.typeMismatch) email.setCustomValidity('Esse e-mail parece incompleto');
});
email.addEventListener('input', () => email.setCustomValidity(''));

19 · FORMULÁRIOS COM JAVASCRIPT

Enviando sem recarregar a página

Acessando formulários e campos

const form = document.forms.contato;      // pelo name do form
form.elements.email.value;                 // campo pelo name
form.elements.plano.value;                 // valor do radio marcado!
form.elements.length;                      // quantidade de campos

Enviando com fetch + FormData

form.addEventListener('submit', async (event) => {
    event.preventDefault();                 // impede o envio tradicional

    const dados = new FormData(form);       // pega TODOS os campos com name
    const botao = event.submitter;          // qual botão foi clicado
    botao.disabled = true;                  // evita clique duplo

    try {
        const resposta = await fetch(form.action, {
            method: form.method,
            body: dados                     // já vai como multipart/form-data
        });
        if (!resposta.ok) throw new Error('Falha no envio');
        form.reset();
    } catch (erro) {
        alert(erro.message);
    } finally {
        botao.disabled = false;
    }
});

Truques com FormData

// Converter para objeto / JSON
const objeto = Object.fromEntries(new FormData(form));
JSON.stringify(objeto);

// Campos com vários valores (checkbox)
new FormData(form).getAll('hobby');   // ['ler', 'correr']

// Adicionar dados extras
const fd = new FormData(form);
fd.append('origem', 'site');

// Mandar como query string (GET)
const params = new URLSearchParams(new FormData(form));
fetch('/buscar?' + params);

Eventos importantes

EventoQuando dispara
inputA cada tecla/alteração
changeQuando o valor é "confirmado" (sair do campo, escolher opção)
submitAo enviar (no <form>, não no botão!)
resetAo limpar o formulário
invalidQuando um campo falha na validação
formdataQuando um FormData é criado — dá para injetar campos
⚠️ submit() x requestSubmit(): form.submit() envia sem validar e sem disparar o evento submit. Use form.requestSubmit(), que se comporta como um clique real no botão.

            20 · HACKS E TRUQUES AVANÇADOS
            
O que os seniores sabem

            

                

                    

                        
1. Campo fora do form (atributo form)

                        
Um campo pode pertencer a um formulário estando em qualquer lugar da página — até dentro de outro form.

                        
<form id="busca" action="/buscar"></form>

<header>
    <input name="q" form="busca">
    <button form="busca">🔍</button>
</header>

                    

                    

                        
2. method="dialog"

                        
Dentro de um <dialog>, fecha o modal sem enviar nada. O value do botão vira o returnValue.

                        
<dialog id="confirmar">
    <form method="dialog">
        <p>Excluir item?</p>
        <button value="nao">Cancelar</button>
        <button value="sim">Excluir</button>
    </form>
</dialog>
<!-- confirmar.returnValue === 'sim' -->

                    

                    

                        
3. Travar tudo com fieldset disabled

                        
Evite envio duplicado desabilitando o formulário inteiro durante o fetch.

                        
<form>
    <fieldset id="campos"> ...todos os campos... </fieldset>
</form>

campos.disabled = true;  // trava
await fetch(...);
campos.disabled = false; // destrava

                    

                    

                        
4. Honeypot anti-spam

                        
Um campo escondido que humanos não veem, mas robôs preenchem. Se vier preenchido, descarte no servidor.

                        
<div style="position:absolute; left:-9999px" aria-hidden="true">
    <label>Não preencha
        <input name="website" tabindex="-1" autocomplete="off">
    </label>
</div>

                    

                    

                        
5. Abrir o seletor via JS: showPicker()

                        
Abre o calendário, seletor de cor, arquivo ou datalist a partir de qualquer botão.

                        
botao.addEventListener('click', () => {
    inputData.showPicker();
});

                    

                    

                        
6. Mostrar/ocultar senha

                        
Basta trocar o type. Lembre do type="button"!

                        
<button type="button" onclick="
  senha.type = senha.type === 'password' ? 'text' : 'password'
">👁️</button>

                    

                    

                        
7. Upload de pasta e câmera

                        
Seleção de diretório inteiro ou foto direto da câmera no celular.

                        
<input type="file" webkitdirectory>
<input type="file" accept="image/*" capture="environment">

                    

                    

                        
8. Preview de imagem antes do upload

                        
Sem enviar ao servidor: o navegador cria uma URL temporária.

                        
input.addEventListener('change', () => {
    img.src = URL.createObjectURL(input.files[0]);
});

                    

                    

                        
9. Estilizar com :has()

                        
O pai reage ao estado do filho — sem JS.

                        
/* Card fica marcado quando o radio dentro dele é escolhido */
.plano:has(input:checked) { border-color: #ff6b35; }

/* Form mostra aviso se tiver algum campo inválido */
form:has(:user-invalid) .aviso { display: block; }

                    

                    

                        
10. Botão de submit com nome e valor

                        
Descubra no servidor qual botão foi clicado.

                        
<button name="acao" value="aprovar">Aprovar</button>
<button name="acao" value="rejeitar">Rejeitar</button>
<!-- Enviado: acao=aprovar -->

                    

                    

                        
11. Bloquear rodinha no type="number"

                        
Evita que o valor mude ao rolar a página com o mouse em cima do campo.

                        
document.addEventListener('wheel', () => {
    if (document.activeElement.type === 'number') {
        document.activeElement.blur();
    }
});

                    

                    

                        
12. Avisar antes de sair com dados não salvos

                        
Evite perder um formulário longo preenchido pela metade.

                        
let sujo = false;
form.addEventListener('input', () => sujo = true);
form.addEventListener('submit', () => sujo = false);
window.addEventListener('beforeunload', (e) => {
    if (sujo) e.preventDefault();
});

                    

                    

                        
13. Busca que já funciona sem JS

                        
Use <search> (novo elemento semântico) com method="get": a URL resultante pode ser compartilhada.

                        
<search>
    <form action="/produtos" role="search">
        <input type="search" name="q" enterkeyhint="search">
    </form>
</search>

                    

                    

                        
14. Resetar a aparência nativa

                        
Remove o estilo padrão do sistema para criar seu próprio design.

                        
select, input[type="checkbox"] {
    appearance: none;
}
/* 🆕 select customizável (Chromium) */
select, ::picker(select) {
    appearance: base-select;
}

            21 · SEGURANÇA
            
Nunca confie no que vem do formulário

            

                
Tudo que está no navegador pode ser alterado pelo usuário. O HTML ajuda na experiência, mas a segurança mora no servidor.

                

                    
RiscoComo se proteger

                    
                        
Burlar validação do HTMLRevalide todos os dados no back-end

                        
Dados interceptadosUse sempre HTTPS; o navegador alerta formulários de senha em HTTP

                        
Senha na URLUse method="post" para dados sensíveis

                        
CSRF (site falso envia form para o seu)Token secreto em <input type="hidden"> + cookies SameSite

                        
XSS (injetar script pelo campo)Escape o conteúdo ao exibir; nunca use innerHTML com dados do usuário

                        
SQL InjectionConsultas parametrizadas no banco de dados

                        
Upload maliciosoVerifique tipo real, tamanho e renomeie o arquivo no servidor

                        
Spam e robôsHoneypot, rate limit e CAPTCHA quando necessário

                        
Força bruta no loginLimite de tentativas e mensagens genéricas ("usuário ou senha inválidos")

                    
                

                
<form action="/transferir" method="post">
    <!-- Token gerado pelo servidor, único por sessão -->
    <input type="hidden" name="csrf_token" value="a8f5f167f44f4964e6c998dee827110c">
    ...
</form>

                

                    ⚠️ Lembre: type="hidden", readonly e disabled não protegem nada. O usuário pode alterar qualquer valor pelo DevTools antes de enviar (inclusive o preço de um produto!).
                

            

        


        
        

            22 · ACESSIBILIDADE EM FORMULÁRIOS
            
Formulários para todas as pessoas

            

                
Um formulário inacessível é um formulário que não funciona para milhões de pessoas — e as diretrizes WCAG exigem que funcione.

                
Checklist de acessibilidade

                
    
                    
  • ✅ Todo campo tem um <label> visível e associado
    • 
                    
  • ✅ Grupos de radio/checkbox dentro de <fieldset> + <legend>
    • 
                    
  • ✅ Instruções e erros ligados ao campo com aria-describedby
    • 
                    
  • ✅ Campos com erro marcados com aria-invalid="true"
    • 
                    
  • ✅ Erros anunciados com aria-live ou role="alert"
    • 
                    
  • ✅ Erro não indicado apenas por cor (use ícone + texto)
    • 
                    
  • ✅ Ordem de foco lógica e foco sempre visível (:focus-visible)
    • 
                    
  • ✅ Tudo funciona só com teclado (Tab, Shift+Tab, Espaço, Enter, setas)
    • 
                    
  • ✅ Área de clique de pelo menos 24×24px (ideal 44×44px no celular)
    • 
                    
  • ✅ Obrigatoriedade informada no texto, não só com *
    • 
                

                
<label for="senha">Senha (obrigatório)</label>
<input type="password" id="senha" name="senha" required
       aria-describedby="senha-dica senha-erro"
       aria-invalid="true">
<p id="senha-dica">Mínimo de 8 caracteres, com um número.</p>
<p id="senha-erro" role="alert">⚠️ A senha precisa ter um número.</p>

                
Quando não há label visível

                
<!-- Opção 1: aria-label -->
<input type="search" name="q" aria-label="Buscar no site">

<!-- Opção 2: label escondido visualmente (mas lido pelo leitor de tela) -->
<label for="q" class="sr-only">Buscar no site</label>

.sr-only {
    position: absolute; width: 1px; height: 1px;
    overflow: hidden; clip-path: inset(50%); white-space: nowrap;
}

                

                    💡 Teste você mesmo: desconecte o mouse e tente preencher seu formulário só com o teclado. Depois teste com um leitor de tela (NVDA no Windows, VoiceOver no Mac/iPhone).
                

            

        


        
        

            23 · BOAS PRÁTICAS DE UX
            
Formulários que as pessoas terminam

            

                

                    

                        
✅ Sempre faça

                        
    
                            
  • Peça só o necessário — cada campo a mais reduz conversões
    • 
                            
  • Uma coluna só: o olho segue de cima para baixo
    • 
                            
  • Label acima do campo
    • 
                            
  • Use o type, inputmode e autocomplete corretos
    • 
                            
  • Mostre o formato esperado antes do erro
    • 
                            
  • Valide ao sair do campo, não a cada tecla
    • 
                            
  • Botão com verbo claro: "Criar conta", não "Enviar"
    • 
                            
  • Dê feedback de carregamento e de sucesso
    • 
                            
  • Divida formulários longos em etapas
    • 
                            
  • Permita colar em todos os campos
    • 
                        

                    

                    

                        
❌ Nunca faça

                        
    
                            
  • Placeholder no lugar de label
    • 
                            
  • Bloquear colar em senha ou e-mail
    • 
                            
  • Botão "Limpar" ao lado de "Enviar"
    • 
                            
  • Apagar os dados após um erro
    • 
                            
  • Mostrar erros antes do usuário digitar
    • 
                            
  • Campos "confirme seu e-mail" desnecessários
    • 
                            
  • CAPTCHA logo de cara
    • 
                            
  • Desabilitar o botão sem explicar o motivo
    • 
                            
  • Selects gigantes para poucos itens (use radio)
    • 
                            
  • Separar nome em 3 campos sem necessidade
    • 
                        

                    

                

                
Qual campo usar?

                

                    
SituaçãoMelhor escolha

                    
                        
2 a 5 opções, uma escolhaRadio

                        
Mais de 5 opções, uma escolhaSelect

                        
Muitas opções + texto livreInput + datalist

                        
Várias escolhasCheckboxes

                        
Sim/NãoUm checkbox

                        
Número de 1 a 5Radio ou range
